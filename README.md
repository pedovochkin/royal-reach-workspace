# Royal Reach — Sales Workspace

Самостоятельный интерактивный frontend-прототип CRM и обучения продажам. Написан на React и CSS, собирается в статические файлы. Не использует Sites, серверные API, ключи или реальные персональные данные.

## Запуск

```sh
npm install
npm run build
npm run dev
```

Откройте http://127.0.0.1:4173. Для публикации загрузите содержимое `dist/` на любой статический хостинг. Относительные пути позволяют публиковать приложение в подкаталоге GitHub Pages. Навигация использует hash-маршруты.

## Сценарий демонстрации

1. «Мой день» → «Переписки» → Алексей → «Разобрать диалог».
2. «Создать учебный пример» → отредактировать вывод → «Утвердить для обучения».
3. Открыть «Базу знаний»: утверждённый пример появляется в материалах. Поиск показывает текст и источник.
4. «Академия» → продолжить обучение → прочитать правило → ответить на тест → написать ответ учебному клиенту.
5. В практике нужно уточнить задачу, задать вопрос и предложить следующий шаг. После успешного прохождения открывается следующий блок и начисляются баллы.
6. В карточке клиента можно изменить этап; можно добавить вымышленного клиента, задачу или учебный материал.
7. Настройки внизу меню позволяют экспортировать демоданные и сбросить макет с отдельным подтверждением.

## Границы прототипа

- Данные хранятся в `localStorage` только этого браузера. Между устройствами они не синхронизируются.
- Переписки и люди вымышлены. Введённые сообщения никому не отправляются.
- ИИ-подсказки — подготовленные демонстрационные сценарии. Проверка свободного ответа использует простые локальные признаки, а не нейросеть.
- Нет авторизации, серверного разграничения прав, реальных уведомлений и интеграций Telegram/MAX/OpenAI/Supabase. Экран интеграций объясняет план подключения.
- Режим наставника демонстрирует рабочий процесс и не является защитой доступа.
- Основной интерфейс работает без внешних запросов. Шрифт Golos Text загружается с Google Fonts, при недоступности используется системный шрифт.

## Проверки

```sh
npm test
npm run build
```

Логика проверки практики, восстановления состояния и поиска проверяется встроенным `node:test`. Интерфейс дополнительно проверяется в браузере на desktop и мобильном размере.

## Будущая рабочая версия

Обработчики мессенджеров и GPT API должны выполняться на сервере. Ключи нельзя помещать в frontend. Перед подключением MAX нужно подтвердить допустимый способ доступа к требуемым перепискам. Supabase хранит историю и утверждённые материалы; поиск отбирает контекст для модели. Реальные оценки сотрудников требуют проверяемых цитат и проверки наставника.
