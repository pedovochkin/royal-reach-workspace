# Royal Reach CRM

Публичный frontend-макет CRM и обучения продажам на вымышленных данных. Тёмный интерфейс с красными акцентами переработан по предоставленному пользователем референсу.

- [Руководитель](https://pedovochkin.github.io/royal-reach-workspace/?v=crm-5&role=manager#overview)
- [Сотрудник](https://pedovochkin.github.io/royal-reach-workspace/?v=crm-5&role=employee#overview)

## Пять разделов

1. **Мой день:** открытые и просроченные задачи, диалоги без ответа, сделки в работе и ожидающие оплаты. Кнопки счётчиков открывают соответствующий фильтр. Задачи упорядочены по сроку.
2. **Клиенты и сделки:** таблица, поиск, фильтр этапа, карточка клиента и создание контакта. Руководитель может выбрать ответственного, сотрудник создаёт контакт для себя.
3. **Переписки:** MAX и Telegram, поиск, фильтр «Требуют ответа», сохранение учебных сообщений и демонстрационный разбор. Просмотр чата не снимает необходимость ответить: из очереди диалог выходит после сообщения сотрудника.
4. **Разбор продаж:** список диалогов, учебные выводы и очередь проверки. Сотрудник отправляет вывод, руководитель утверждает его для общей базы знаний.
5. **Обучение:** руководитель видит прогресс пяти сотрудников, сотрудник — четыре последовательных блока и ежедневную практику на 15–30 минут. База знаний находится в отдельной вкладке этого раздела.

В верхней панели находятся общий поиск по доступным клиентам и выбор роли. На телефоне меню открывается кнопкой слева. Промоблоки, отдельный экран интеграций, дополнительные варианты отображения и декоративная геймификация убраны из основного интерфейса.

## Что проверить

- «Просрочено» на главном экране → только просроченные задачи. Выполнение задачи обновляет счётчик.
- «Ожидают оплаты» → таблица со сделками на этом этапе.
- «Без ответа клиенту» → соответствующий фильтр и первый подходящий чат.
- Создание задачи с клиентом: точная дата и время или «В течение 24 часов» с отсчётом от сохранения. Срок виден в списке и карточке, после истечения задача становится просроченной.
- Переключение роли → сотруднику доступны только свои клиенты и задачи; поиск не возвращает клиентов коллег.
- «Разбор продаж» → предложить вывод сотрудником → проверить и утвердить руководителем → материал появляется во вкладке «База знаний».
- «Обучение» → правило, тест, свободный ответ → следующий блок открывается после успешной практики.

## Структура

- `src/main.jsx` — оболочка, пять пунктов меню, чат, клиенты, формы и модальные сценарии.
- `src/crm.jsx` — главный экран, список разборов и обучение.
- `src/crm.css` — актуальная тёмная тема и адаптивные компоновки.
- `src/crm-model.mjs` — сроки задач и определение диалогов, требующих ответа.
- `src/ui.jsx` — общие элементы, SVG-пиктограммы и модальные окна.
- `src/access.mjs` — фильтрация данных и ограничения изменений для демороли сотрудника.
- `src/model.mjs` — демонстрационные данные, сохранение, проверка ответа и поиск знаний.
- `src/workspaces.jsx` — переиспользуемое окно профиля сотрудника; прежние страницы из файла не используются.
- `src/style.css` — базовые размеры и раскладки общих элементов.

Системные шрифты, собственные SVG, без внешних визуальных зависимостей. Сборка добавляет хеш к URL CSS и JavaScript.

## Запуск

```sh
npm install
npm run build
npm run dev
npm test
```

Локальный сервер: http://127.0.0.1:4173. Семь тестов проверяют восстановление данных, оценку практики, поиск утверждённых знаний, демороли, сроки и очередь ответов. В браузере проверены фильтры, создание и выполнение задачи, поиск обеих ролей, обучение и экран шириной 390 px.

## Границы макета

Все люди и переписки вымышлены. Сообщения никому не отправляются. Данные сохраняются в localStorage только этого браузера, без синхронизации между устройствами. Новые задачи используют фактическое время и часовой пояс Москвы (UTC+3). Начальные задачи без сохранённой даты показываются относительно текущего дня. Старые демоданные и прогресс сохраняются.

ИИ-разборы показывают подготовленные сценарии; оценка свободного ответа выполняется локально по учебным признакам. Настоящие GPT API, Telegram, MAX и Supabase не подключены. Переключение роли демонстрирует ограничения интерфейса, не является авторизацией. Для реальной защиты нужны серверная проверка прав и Supabase RLS.
